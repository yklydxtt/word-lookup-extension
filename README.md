# 离线划词查词

面向英文网页阅读的轻量 Chromium 浏览器扩展。双击或拖动选中一个英文单词，即可在附近查看中文释义、音标，并按需播放本地英语发音。

**内置词库 · 无需账号或 API Key · 运行时离线查词 · 不改写网页正文**

当前版本：`0.1.0`，基于 Manifest V3。主要实机验收环境为 `ego lite`；Chrome、Edge 是兼容目标，尚未完成独立实机验证。

## 界面预览

![在 Wikipedia 网页中选中 public 后显示离线查词卡片](docs/qa/ego-lite-wikipedia-public.png)

截图来自 `ego lite` 中实际安装的扩展：在 Wikipedia 网页正文中双击选中 `public`，等待扩展从内置词库返回完整释义后截取。页面没有预置或模拟查词卡片，详细验收说明见[首版验收记录](docs/qa/ego-lite-acceptance.md)。

## 功能特点

| 功能 | 说明 |
| --- | --- |
| 选词即查 | 双击或拖动选中单个英文单词，自动显示查询卡片 |
| 离线英汉词典 | 内置 399,213 条词条，展示词库收录的中文释义、音标和词性 |
| 词形回查 | 优先匹配原词条；未命中时按词库中的明确关联回查原形，并标明结果对应的词 |
| 本地发音 | 点击后才朗读，仅使用浏览器明确标记为本地的系统英语语音，英式优先、美式兜底 |
| 网站级开关 | 支持全局启停，以及按网站域名单独启停；设置仅保存在本地 |
| 低干扰阅读 | 不给正文批量添加下划线、高亮或按钮，卡片使用 Shadow DOM 隔离样式 |
| 小猫标识 | 工具栏、扩展管理页与菜单使用「蜷睡猫」图形 |

词典会列出多个释义，**不会根据上下文自动判断词义，也不提供整句翻译**。

## 快速开始

本仓库提供源码，`dist/`、下载缓存和生成词库不纳入版本控制。首次使用需要先构建，再将 `dist/` 加载到浏览器；下载源码 ZIP 本身不等于获得可安装的扩展包。

### 1. 准备环境

- Node.js **22.12.0 或以上**；已验证环境为 Node.js `22.22.1`、npm `10.9.4`。
- 支持 Manifest V3 的桌面 Chromium 浏览器；构建目标为 Chrome 120。
- 首次安装依赖与准备词库时，需要访问 npm 公共源和 `raw.githubusercontent.com`。

在终端进入下载或克隆后的项目根目录，执行：

```bash
npm ci --registry=https://registry.npmjs.org --replace-registry-host=always
npm run prepare:dictionary
npm run build
npm run check:package
```

安装命令显式使用 npm 公共源，并替换锁文件中的镜像下载域名，不改变锁定的依赖版本或完整性校验。项目现有锁文件生成于内部镜像环境，直接运行不带这些参数的 `npm ci` 可能仍访问原镜像。

构建成功后，项目根目录下会生成可加载的 `dist/`，其中包括扩展代码、图标、完整离线词库及第三方许可。

### 2. 加载扩展

1. 在 `ego lite` 或 Chrome 地址栏打开 `chrome://extensions/`；Edge 对应 `edge://extensions/`。
2. 开启“开发者模式”，并自行确认浏览器提示。
3. 点击“加载已解压的扩展程序”，选择项目中的 **`dist` 文件夹，而不是项目根目录**。
4. 按浏览器提示处理权限，并确认“离线划词查词”已启用。
5. 刷新已经打开的普通网页，再双击或拖动选中英文单词。

日常查词**不需要启动本地服务，也不需要保持终端开启**。请保留已加载的 `dist/`，不要删除或移动；浏览器会从这个目录读取扩展及词库。

## 使用方法

1. **查词**：选中普通网页正文里的一个英文单词，卡片会自动出现在选区附近。
2. **发音**：点击卡片中的发音按钮。没有可用本地英语语音时会显示提示，不自动切换到在线语音。
3. **关闭卡片**：点击卡片外部、按 `Esc` 或滚动网页。卡片内部滚动、选择释义和点击发音不会触发外部关闭逻辑。
4. **临时停用**：点击浏览器工具栏中的插件图标，关闭全局开关或“在当前网站启用”。

网站设置按 hostname 分别记忆。例如，`docs.example.com` 和 `www.example.com` 互不影响；它不是覆盖所有子域名的通配开关。

## 支持范围

| 支持 | 暂不支持 |
| --- | --- |
| 普通 `http`、`https` 网页顶层文档中的可选文本 | 浏览器内部页面、禁止扩展注入的页面、嵌入式 `iframe` |
| 单个英文单词、词内撇号与连字符 | 短语、整句翻译、上下文词义判断 |
| 词库已有的明确词形关联 | 未收录词的联网补查或推测释义 |
| 普通网页正文 | PDF、图片取词、输入框、可编辑区域及代码编辑器 |

## 权限与隐私

扩展声明以下权限：

| 权限 | 用途 |
| --- | --- |
| `storage` | 通过 `chrome.storage.local` 保存全局开关与停用网站列表 |
| `tts` | 查询可用系统语音，并在点击发音时播放单词 |
| `http://*/*`、`https://*/*` | 在普通网页注入划词逻辑并展示卡片 |

- 不持久记录查词历史，不上传单词、网址或网页正文。
- 查询只读取扩展包内的静态词库；未命中时明确提示，不请求在线词典。
- 发音只选择 `remote === false`、且不由其他扩展提供的系统语音，优先 `en-GB`，其次 `en-US`。
- 不加载远程脚本或在线音频。词库下载发生在开发准备阶段，而不是用户查词时。
- 浏览器、操作系统、网页和其他扩展的网络行为不属于本扩展的请求；完整网络链路尚未完成独立验证，不能将上述实现约束理解为对整个设备零流量的保证。

## 词库与构建

词库来自 [ECDICT](https://github.com/skywind3000/ECDICT)，固定版本为 `bc015ed2e24a7abef49fc6dbbb7fe32c1dadaf8b`。

| 项目 | 当前构建数据 |
| --- | --- |
| 原始 CSV | 65,933,428 字节，770,611 行数据 |
| 生成词条 | 399,213 条 |
| 词形关联 | 56,954 组 |
| 静态分片 | 256 个 |
| 运行时缓存 | 最多 8 个分片、256 条查询结果 |
| 未压缩扩展 | 约 47.43 MiB |

短语、含数字及不符合单词查询规则的行不会进入生成词库；因此，词条数不等于原始 CSV 行数。

`npm run prepare:dictionary` 会下载固定版本 CSV 与许可文件，并校验 CSV 字节数及 Git blob。数据缓存到 `.cache/ecdict/`，分片与 SHA-256 索引生成到 `.generated/dictionary/`；后续准备会复用并重新校验缓存中的 CSV。来源校验失败时立即停止，不使用未验证数据。

`npm run build` **不会自动下载词库**，需要先生成 `.generated/dictionary/`。它重建 `dist/`，打包脚本与词库，并从 `src/assets/cat-logo.svg` 生成 16、32、48、128 像素 PNG 图标。图形库及其他开发依赖不进入扩展运行时代码。

更多来源、校验值及许可信息见 [第三方数据说明](THIRD_PARTY_NOTICES.md)。

## 常见问题

### 选中单词后没有卡片？

先确认扩展已启用、全局与当前网站开关均已打开，并刷新页面。再检查选区是否只有一个英文单词，页面是否属于支持范围；浏览器内部页面、PDF、输入框及编辑器不支持查词。

### 能看到释义，但无法发音？

发音依赖设备和浏览器提供的本地英语语音。确认系统已安装可离线使用的英语语音，必要时重启浏览器；只有明确标记为本地的 `en-GB` 或 `en-US` 语音会被使用。扩展不会为此回退到在线服务。

### 构建提示缺少词库文件？

先运行 `npm run prepare:dictionary`。全新克隆不会包含 `.generated/dictionary/`，单独运行 `build` 不会联网补齐。

### 准备词库时出现校验失败？

不要跳过校验或手改固定版本信息。确认网络下载完整后，移走 `.cache/ecdict/` 中失败的缓存并重新准备；若固定来源仍无法通过校验，应先核对来源配置，再继续构建。

### 为什么源码很小，构建产物却约 47 MiB？

构建产物内置完整的离线词库。仓库只保留源码、来源配置、测试和许可，下载缓存与生成词库不会重复提交。

### 能用于 Firefox、Safari 或手机浏览器吗？

当前目标是桌面 Chromium 浏览器，没有实现或验证 Firefox、Safari 和移动端支持。
